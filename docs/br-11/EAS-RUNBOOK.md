# BR-11 EAS Development Build Runbook

Run EAS commands from `apps/mobile`, not the repository root. This is required for an Expo app living inside a monorepo.

## 1. One-time Expo/EAS project link

From the repository checkout:

```bash
cd apps/mobile
pnpm dlx eas-cli@latest login
pnpm dlx eas-cli@latest init
```

`eas init` must link this app to the intended MyFan Expo project. Review any generated `extra.eas.projectId` before committing it. Do not invent or reuse another application's project ID.

## 2. Configure public build environment

The native client needs the same public Supabase endpoint and publishable/anon key used by Mobile Web:

- `EXPO_PUBLIC_MYFAN_ENV=development`
- `EXPO_PUBLIC_SUPABASE_URL=https://asnydvqsduonyidjyyzq.supabase.co`
- `EXPO_PUBLIC_SUPABASE_ANON_KEY=<current publishable/anon key>`
- financial execution feature flags remain `false`
- `EXPO_PUBLIC_FEATURE_GOOGLE_AUTH` remains `false` until native OAuth redirect configuration is verified

Never configure `service_role`, `sb_secret_*`, PII encryption keys, banking credentials, or Google OAuth client secrets in an `EXPO_PUBLIC_*` variable.

Prefer EAS environment variables/secrets rather than committing key values to `eas.json`.

## 3. Supabase Auth redirect for native

Before testing Google OAuth or password recovery in the native build, add this redirect URL in Supabase Authentication URL Configuration:

```text
myfan://auth/callback
```

Web redirects already remain separate. The native callback is generated by `Linking.createURL('auth/callback')` using the `myfan` scheme.

## 4. Build Android development APK

```bash
cd apps/mobile
pnpm dlx eas-cli@latest build --platform android --profile development
```

Expected profile properties from `eas.json`:

- `developmentClient: true`
- `distribution: internal`
- Android `buildType: apk`
- package ID: `com.myfan.mobile.dev`

Do not use this development package ID as the BR-12/production Play package decision.

## 5. Start Metro for the installed development client

```bash
cd apps/mobile
pnpm dev
```

Open the installed MyFan development client and connect it to the Metro server. A development build, not Expo Go, is required for final BR-11 deep-link and native-module verification.

## 6. Deep-link smoke tests

With the development build installed, verify at minimum:

```text
myfan://auth/callback
myfan://profile/myfan1
myfan://activity/myfan1
```

Expo Router should open the corresponding native route. Do not implement a WebView fallback.

## 7. Roll forward / rebuild rule

Any change to `app.json` native plugins, permissions, scheme, Android package ID, or native dependency requires a new development build. Pure TypeScript/UI changes can continue through Metro without rebuilding the native binary unless the dependency/native configuration changes.

## 8. Evidence to retain

For BR-11 closure record:

- EAS build URL/ID.
- Git commit SHA built.
- APK artifact/version.
- Android device/API matrix results.
- Session restore evidence after force-close/reopen.
- camera/library/location grant + deny evidence.
- deep-link evidence.
- lifecycle/background reconnect evidence.
- confirmation that no WebView replacement exists.
